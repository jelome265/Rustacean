Preview first. Then apply.

The default is a dry run that writes nothing. Installation is a separate, explicit step, and the installer verifies what it wrote.

  1. Install the package

    Node.js 18+ and Python 3. The package bundles the installer and all five skills. No frontend build step.

  2. Preview the plan

    A dry run prints what would change. Nothing is written.

  3. Apply and verify

    Writes the files, then checks content hashes and peer links.

  4. Confirm the agent loads them

    Installed is not discovered. See the discovery checks.

Five skills, one standard.

The five skills refer to one another, and the installer refuses to install a partial suite.

  • RS-01

    Best practices

    Rulebook

    Stable BP-* rule IDs, workspace lint policy, and explicit controls against risky Rust patterns.

    Use for
    Any Rust code written, reviewed, refactored or configured.
    Role
    The baseline the other four depend on.
  • RS-02

    Implementation

    Build

    A requirements-first procedure for turning an agreed design into maintainable Rust code.

    Use for
    Creating or extending crates, services, CLIs and libraries.
    Role
    Every rule it applies cites a BP-* rule.
  • RS-03

    Hardening

    Harden

    Security, resilience, observability, operational readiness, build discipline and container controls.

    Use for
    Services that handle untrusted input, money, personal data or credentials.
    Role
    Builds on the rulebook baseline.
  • RS-04

    Read-only audit

    Inspect

    Evidence-based security and logic findings, each with severity, location at a pinned commit, reproduction and remediation.

    Use for
    Security reviews, pre-launch reviews, and second opinions on Rust services.
    Role
    Never modifies code and never merges anything.
  • RS-05

    Framework controls

    Control

    An approved framework stack, prohibited patterns, and executable inventory checks that keep dependencies aligned with policy.

    Approved stack
    tokio, axum, tonic, sqlx, reqwest, serde, tracing with OpenTelemetry, clap, rustls.
    Enforcement
    Clippy disallowed-method and disallowed-type bans, plus route and client inventory tests.

Guidance, then checks.

Skills guide agent behaviour. They do not replace compilers, tests, CI or human review. This is what each part does.

Written for the agent

  • Rules with stable IDs that plans, reviews and audit findings can cite.
  • Procedures for implementing, hardening and auditing Rust code.
  • An approved stack and banned alternatives, described in plain language.

Checked by tools

  • Clippy disallowed-method and disallowed-type lists.
  • Route and client inventory tests for the approved stack.
  • The installer's content-hash and peer-link verification after an apply.

Where a rule has no check, it is guidance. The audit skill reports findings with evidence, but a finding is a claim to verify, not a verdict.

  2. List the skills in the agent. Confirm all five appear.
  3. Check each agent separately if you use more than one.
