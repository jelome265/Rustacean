01 / Quick install

Start with the source.
Apply only what you review.

Install the package in your project, inspect the proposed file changes, then apply and verify the complete skill suite. The default is a dry run; installation is an explicit action.

Requirements

Node.js 18+, Python 3, and a supported coding agent. The npm package bundles the installer and all five skills. No framework or frontend build step is required.

Read the installation guide ↗

TERMINAL / PROJECT ROOTnpm
$ npm i rustacean-skills

$ npx rustacean-skills --list

$ npx rustacean-skills --agent codex --project-root .
$ npx rustacean-skills --agent codex --project-root . --apply

Review the dry-run plan first. Add --apply only when you are ready to install.

02 / The skill suite

Five roles.
One coherent engineering standard.

The skills are designed to work together. They share rule IDs and references, and the installer rejects partial installations because the suite is intentionally connected.

RS / 01

Best practices

The normative rulebook: stable rule IDs, workspace lint policy, and explicit controls against risky Rust patterns.

RS / 02

Implementation

A requirements-first procedure for turning an agreed design into maintainable Rust code.

RS / 03

Hardening

Security, resilience, observability, operational readiness, build discipline, and container controls.

RS / 04

Read-only audit

Evidence-based security and logic findings, with a workflow designed to inspect rather than modify the target.

RS / 05

Framework controls

An approved framework stack, prohibited patterns, and executable inventory checks to keep dependencies aligned with policy.

03 / Method

Guidance is useful.
Verification makes it accountable.

Rustacean combines written instructions with checks where automation can provide evidence. Skills guide agent behavior; they do not replace compilers, tests, CI, or human review.

01 / RULES

Stable references

Rules have identifiers that can be cited in implementation plans, reviews, and audit findings.

02 / POLICY

Lint as code

Workspace lints and tested gates turn selected prohibitions into build-time feedback.

03 / EVIDENCE

Checkable output

Installation hashes, peer-link checks, tests, and CI supply evidence instead of relying only on claims.

04 / BOUNDARIES

Review remains

Read the skills, examine proposed changes, and keep the normal review and release controls in place.

04 / Compatibility

Meet the agent where it works.

The installer documents skill discovery paths for a range of coding agents. Documentation evidence varies by target, so it distinguishes official paths from conflicting or third-party references.

05 / Verify

File installation is not agent discovery.

After applying the plan, the installer checks content hashes and peer links. Start a new session or restart your agent, then confirm that it actually lists the five Rustacean skills.

A successful installer run confirms that files are present and verified. It does not prove that the target agent loaded or followed them. Check discovery separately.
